# Codex 总任务：完成 FlyPPTTimer 4.0 WPF 重构与 v0.30.2 全功能复现

## 一、最终目标

在 `agent/v4-foundation` 分支上，由 Codex 自主完成 FlyPPTTimer 4.0 的完整构建。

最终产品必须：

1. 以 WPF 作为正式桌面界面和主入口。
2. 对 `v0.30.2` 的全部用户功能、模块、下属子功能、配置语义和关键交互实现功能等价。
3. 在功能等价的前提下完成模块化重构，消除超大类、UI 与业务逻辑混杂、同步线程互锁、资源生命周期不清晰等问题。
4. 保持现有配置可迁移，已有用户升级后不得丢失设置、文件规则、远程 token 或自定义提示音。
5. 每个阶段都产生可运行的 Windows x64 Artifact，而不是只交付内部组件。
6. 完成用户说明、开发说明、架构说明、迁移说明、功能对照表和测试报告。

稳定行为基线固定为 Git 标签：

```text
v0.30.2
```

不得把不断变化的 `main` 当作唯一基线。当前 4.0 分支已有的正确重构、测试和 WPF 设置实现应保留并继续利用。

## 二、工作方式

这是 Codex 主导的连续工程，不再等待外部逐个拆分任务。

开始时执行：

```powershell
git fetch --all --tags --prune
git checkout agent/v4-foundation
git pull --ff-only origin agent/v4-foundation
git status --short
git rev-parse HEAD
git rev-parse v0.30.2
```

除 `artifacts/`、`bin/`、`obj/` 等生成目录外，如存在来源不明的工作区修改，停止并如实报告，不得重置或覆盖。

### 连续执行规则

- 按本文件阶段顺序连续工作，不需要每完成一个小组件就等待用户确认。
- 每个阶段完成后提交并推送到同一分支，然后继续下一阶段。
- 每个阶段只允许一个或少量有完整意义的提交，禁止大量“接口—测试—接线”微提交往返。
- 若当前会话容量不足，必须先把可用状态提交并推送，并更新：

```text
docs/v4/V4_PROGRESS.md
```

进度文件必须写明：

- 当前阶段和完成百分比
- 已完成模块与提交 SHA
- 未完成模块
- 当前失败测试或已知风险
- 下一步准确文件和任务
- 下一次 Codex 对话可直接使用的恢复指令

不得仅在聊天中保存关键上下文。

### C. 提醒、声音和到时动作

- 两次提前提醒与结束提醒

- 语音提醒

### D. 普通计时窗口

- 显示/隐藏并允许后台计时

- 仅扩展屏可用，主屏排除

### F. 文件规则

## 五、重构要求

### 分层原则

允许根据现有代码实际情况调整项目数量，但必须形成清晰边界：

- Domain/Core：计时状态、规则、纯模型和纯逻辑
- Application：用例、命令、协调和状态投影
- Infrastructure.Windows：配置、日志、热键、显示器、音频、语音、进程、窗口和更新
- Presentation Integration：PowerPoint/WPS/全屏检测
- Remote：HTTP、鉴权、协议、网页资源和远程状态同步
- WPF Desktop：窗口、ViewModel、导航、主题和本地化

禁止：

- 新建一个替代旧 `FlyPPTTimerContext` 的超大类
- ViewModel 直接操作 COM、进程、HTTP 监听器或磁盘
- UI code-behind 承担业务逻辑
- 用源码字符串断言代替主要行为测试
- 为通过测试而禁用功能
- 静默吞掉异常
- 在 UI 线程同步等待子进程、COM、网络或文件操作
- 无边界的全局静态状态

### 兼容策略

- 在 WPF 功能尚未完整覆盖前，允许旧 WinForms 作为暂时兼容实现。
- 每迁移一个模块，必须将正式入口切到新实现并保留回归测试。
- 只有功能矩阵全部通过后，才能删除经典设置和旧 WinForms 主入口。
- 删除旧代码前必须证明没有仍被调用的功能、配置或远程协议。

## 六、实施阶段

### 阶段 0：审计和架构

交付功能矩阵、架构文档、迁移方案和进度文件。运行 `v0.30.2` 测试作为基准，并记录当前 4.0 测试状态。

### 阶段 1：WPF 应用外壳、计时与显示

交付正式 WPF 主进程或可逐步替换的 WPF 壳，完成计时核心、普通计时窗口、多屏和大屏计时。必须提供可运行 Artifact。

### 阶段 2：完整 WPF 设置、文件规则和提醒

将经典设置中的全部正式设置迁移到 WPF，包括规则、声音、提醒、快捷键、显示和其他设置。完成配置迁移测试。

### 阶段 3：PowerPoint、WPS 和自动联动

完成全部文稿、放映、窗口、关闭和能力检测行为；保留并强化现有 STA、状态监控、窗口激活、检测和终止组件。

### 阶段 4：远程控制

完成桌面远程控制窗口、HTTP 服务、网页/手机端全部功能、语言、手势和安全语义。

### 阶段 5：统一入口、清理旧 UI、更新与发布链

将 WPF 设为唯一正式桌面入口；在矩阵确认后移除不再需要的 WinForms UI。完成更新、安装、便携包、文档和发布验证。

### 阶段 6：全功能验收候选版

生成 4.0 候选 Artifact，执行自动化和人工测试计划；不得直接发布 Release、合并 PR 或修改 `main`。

## 七、每阶段质量门槛

每阶段必须：

1. Release Build 0 warnings / 0 errors。
2. 所有现有测试通过。
3. 为新增或迁移功能增加行为测试。
4. 对关键 WPF 流程增加真实控件 UI Automation。
5. 生成同目录可运行发布文件。
6. 计算 SHA-256。
7. GitHub Actions 全部通过并上传 Artifact。
8. 更新功能矩阵、进度、测试报告和已知风险。
9. 提交和推送到 `agent/v4-foundation`。

关键集成测试至少覆盖：

- 主程序启动、托盘和退出
- WPF 设置连续编辑、保存、取消和重复打开关闭
- 计时状态转换和提醒
- 多屏/DPI 逻辑
- 设置保存后即时应用
- 远程 API 鉴权和状态同步
- PowerPoint/WPS 使用可替换适配器进行自动化测试
