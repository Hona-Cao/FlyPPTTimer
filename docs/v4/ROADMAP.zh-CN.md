# FlyPPTTimer 4.0 渐进式重构路线

## 基本原则

- 4.0 不修改 Microsoft PowerPoint 或 WPS Office；只重构 FlyPPTTimer 内部与它们交互的代码。
- 不一次性替换全部界面。每一阶段必须保持可构建、可测试、可回退。
- `main` 继续作为 0.30.x 稳定线；4.0 工作在独立分支和草稿 PR 中完成。
- 用户主要负责真实 Windows、PowerPoint/WPS、投影仪、多屏和页面显示测试。

## 阶段 1：构建与核心基线

- [x] 创建 `agent/v4-foundation` 分支。
- [x] 建立 `4.0.0-alpha.1` 版本标识。
- [x] 切换到 .NET 10 构建基线。
- [x] 新建不依赖 WinForms/WPF 的 `FlyPPTTimer.Core`。
- [x] 新建可注入时钟的计时状态机及单元测试。
- [x] 修正 CI 中硬编码的旧版本号和产物名称。
- [ ] 用新 Core 替换旧 `TimerService`，保持用户行为不变。

## 阶段 2：配置与应用协调

- [ ] 增加独立 `schemaVersion`。
- [ ] 将配置迁移拆成幂等的逐版本步骤。
- [ ] 拆分 `FlyPPTTimerContext` 的窗口、托盘、更新和演示生命周期职责。
- [ ] 为核心命令和应用状态增加接口及模拟实现。

## 阶段 3：演示软件适配层

- [ ] 定义 FlyPPTTimer 内部的 `IPresentationController`。
- [ ] 把 PowerPoint COM、WPS 检测、窗口激活和能力判断拆成独立组件。
- [ ] 保证演示软件未安装、忙碌、崩溃或不支持命令时，FlyPPTTimer 安全降级。
- [ ] 增加模拟控制器契约测试。

## 阶段 4：WPF 桌面层

- [ ] 首先迁移设置窗口。
- [ ] 然后迁移电脑端远程控制窗口。
- [ ] 最后迁移计时悬浮窗和大屏窗口。
- [ ] 保留托盘、热键、多屏、鼠标穿透和置顶行为。
- [ ] 删除被替代的 WinForms 自绘主题和重复 DPI 换算代码。

## 阶段 5：兼容性和发布

- [ ] 测试 Windows 10/11 与 100%–200% 缩放。
- [ ] 测试单屏、多屏、混合 DPI、投影仪插拔。
- [ ] 测试 PowerPoint/WPS 的真实放映和远程控制。
- [ ] 建立安装版、便携版和测试版独立配置策略。
- [ ] 完成 4.0 正式版升级与回滚说明。
