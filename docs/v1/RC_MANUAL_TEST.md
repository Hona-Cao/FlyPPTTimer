## 一、桌面入口、界面与双屏

1. 正常启动，从 Timer 右键和托盘进入设置/PC Remote；关闭后在同一进程重新打开，最后用托盘退出。确认不白屏、不闪退、不只剩任务栏，退出后能正常再次启动。
2. 用三条临时规则 A/B/C 试普通单选、Ctrl 追加/取消、Shift 范围选择，批量改时长/模式后再普通保存。选中什么就修改什么，批量结果不被旧编辑框回写。端口慢速输入、停顿后仍保留。
3. 设置留一项未应用改动，到 Remote 改另一条规则，再回设置应用；两边修改都保留。此项优先由 Codex 做，不要求用户额外读取 JSON。
4. 在实际 150%/125% 两屏间移动设置、Remote 和计时窗口；启用所选扩展屏的大屏计时并关闭。确认不逐次放大、不跑出屏幕、文字完整，大屏显示及关闭后的启用状态正确。
5. 顺手浏览六页设置、长说明/批量弹窗，切一次中英文并按提示重启，检查布局、字体、焦点、滚动和按钮。只记录不舒服或明显异常的地方，不要求重新设计。

确认常用定位、锁定、鼠标穿透等符合原有使用习惯。PC Remote 演示文稿页只有规则管理是已批准行为，不应恢复放映按钮。

PowerPoint/WPS 分别记录，尽量由 Codex 先用临时 PPTX 完成。用户只走自己实际使用的一条流程：打开、从头/当前页放映、翻页/跳转、黑屏/白屏/恢复、结束，观察规则时长及自动计时。

- 本次修复检查 A：关闭 Office，浏览器进入受白名单支持的全屏并保持一段时间；计时应持续前进，不能每次刷新清零。真正离开后按原设置停止/重置。
- 本次修复检查 B：临时 A 在放映，活动文稿 B 未放映；发翻页等命令时应拒绝错误目标，不能误控 A。A→未知路径→A 不应重开原计时轮次。复杂多窗口构造和错误注入由 Codex 做。

## 三、手机跨设备

手机与电脑同一局域网，使用软件实际地址或二维码连接，执行开始、暂停、继续、重置和显示/隐藏。可以合并完成第二区的演示控制，不重复测试。

停止/重启服务后按当前地址重连；更新令牌或断开设备后旧页不能继续控制，新地址能连接。本机访问 LAN 地址不代表手机链路已经通过。

连接异常只记录提示，不关闭整个防火墙，不公开真实 token/访问二维码。

## 四、声音、TTS 与实际提醒

先在软件内选择自己的 WAV/MP3 等提示音并触发；随后清除自定义音频，单独开启 TTS 再测试。原逻辑优先播放自定义声音，不把“必须两种同时播放”当验收条件。

可设 30 秒倒计时，提示 1 提前 20 秒、提示 2 提前 10 秒，启用后听一次提前提醒和结束提醒：完整可听、顺序正确，无意外重复或截断；闪烁后恢复。确认常用 F7/F8、静音/恢复及分钟调整快捷键。测试后恢复原声音状态。

自动播放 API 成功不等于人耳听感通过；不要求用户分析播放线程。
