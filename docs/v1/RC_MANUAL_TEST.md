## 终审结论

接受为代码冻结候选版，进入用户最终实机验收。本轮不新增源码整改任务，不重新扫描全仓库，不重做已经满意的界面。

这不是“所有功能和实际观感均已验证”的正式发布批准。Office、桌面入口、手机跨设备、混合 DPI、实际声音和旧版升级仍有未完成的验收。未测不等于失败，也不等于通过。

依据：本次提交差异、`CODEX_RESULT.md` 的 RC-2 逐项执行记录、`RC_CANDIDATE.md`、用户批准覆盖项及此前源码审查。RC-2 只修改文档，程序源码未变。55 passed / 0 failed / 1 ignored，以及 Windows 执行结果，均为 Codex 提交的记录，不是 ChatGPT 在用户电脑上亲自复跑；原始执行日志仍在本机 `target/rc-temp/`。

已核对截图生成来源：`src/capture.rs` 使用离屏软件渲染，Remote 预览还使用示例数据；不能据此签收真实 Windows 字体、焦点、跨屏尺寸或实际连接状态。本次未能在审阅环境直接打开仓库 PNG，不宣称已经完成图片观感审查。

本文件取代此前分散的待手测条目。下面五组是剩余实机确认的统一入口，不必回头逐份重做历史任务单。

## 1. 桌面入口、PC Remote、双屏和界面

| 1D | 在“下次服务端口”慢慢输入，停顿几秒再完成并应用；核对显示的新地址。服务启停、复制地址和重新生成令牌与第 3 组连着做。 | 输入不跳回旧值；应用后的当前端口、地址和手机实际连接一致。PC“演示文稿”页只做规则管理，不应恢复放映控制按钮。 | 待测 |

## 2. PowerPoint / WPS 的真实演示工作流

原因：RC-2 发现 WPS 已有用户文稿，为保护文件未执行 Office 控制，因此此项不能按“已安装”算通过。PowerPoint 和 WPS 分开测，并分别记结果；不要让两个软件中的真实文稿参与测试。

演示控制使用手机/浏览器 Web Remote，不在 PC Remote 规则页寻找已经按用户要求删除的控制按钮。本组与第 3 组可一次完成，不必重复走流程。

| 编号 | 一次性操作 | 通过标准 | 结果 |
|---|---|---|---|
| 2A | 用临时文稿测试打开、从头放映、从当前页放映、上一页/下一页、跳转、黑屏/白屏/恢复、结束放映。给一份文稿设独立时长规则，另一份用全局时长。 | 操作作用于正确文稿，页码和画面一致；自动开始使用正确规则/全局时长；离开放映时按现有停止/重置开关处理。 | PowerPoint：待测；WPS：待测 |
| 2B | 用短计时分别查看“仅提示”“黑屏并显示时间到”“退出放映”；观察提醒、超时和重新计时。 | 仅提示按超时开关继续；其他到时动作符合所选行为，不停留在无法退出的黑屏，不意外关闭文稿。重新计时可开始新一轮。 | 待测 |
| 2C | 仅用可丢弃文稿检查关闭当前/最后打开文稿、退出演示软件等现有入口的目标和确认提示；确认取消不执行。单独退出 FlyPPTTimer。 | 不关闭错误文稿；单独退出计时器不退出 Office。强制退出只在所有真实工作均已保存关闭后测试，确认文案明确提示未保存内容风险。不要用真实未保存工作试验。 | 待测 |
| 2D | 多放映专项：通过演示软件自身构造 A/B 同时放映，切换活动文稿并发命令；再激活未放映的 C。 | 活动 A/B 时仅控制匹配窗口；目标不明确时提示失败，不随便控制首个窗口，不因歧义误停/重置当前自动计时。无法安全构造就记“未测”；不能据此宣称多放映支持已实机通过。 | 待测 |
