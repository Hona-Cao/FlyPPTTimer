# 当前任务：UX-03 PC Remote 可读性与操作层级

当前分支：`codex/v1-06-manual-test`

## 审核结论

UX-02 设置页布局与 Remote 原生缩放的当前源码审核通过，可保留实现，不要重做。

确认可保留：

- `PresentationWindow` 从固定 `width/height` 改为原生 `preferred-* / min-*` 窗口约束；
- Remote 默认尺寸继续约为 700×620，不增加尺寸持久化、恢复逻辑或自绘 resize grip；
- `FieldRow` 取消每行独立卡片，继续以现有 section 行作为分组边界；
- 标签列、控件列和普通行高度按可用宽度/文字高度调整；
- 文件规则名称/时长/模式与路径的两行展示；
- 规则详情区给路径和编辑控件更多宽度；
- 设置底部 dirty 提示与确定/取消/应用保持分离；
- 本轮只运行一次 `cargo check`，符合风险分层测试策略。

Remote 原生缩放的真实拖拽手感、设置六页真实显示效果仍属于用户真机验收项，但不阻塞继续执行下一轮 UX 优化。

现在正式进入 `docs/v1/UX_OPTIMIZATION_PLAN.md` 的 **UX-03：PC Remote 可读性与操作层级**。

---

## 1. 本轮范围

仅优化桌面 `PresentationWindow` / PC Remote 的信息排布、文字可读性和操作层级。

本轮仍主要限制在 `ui/app-window.slint`。如确实需要读取已有状态字段，可使用现有属性；不要为了视觉层级新增 Rust 状态模型或协议字段。

不要修改手机 Web Remote。

---

## 2. 连接页：突出真正需要看的信息

当前连接页已有：

- 服务状态；
- 当前端口；
- 客户端数量；
- 推荐访问地址；
- 地址列表；
- QR；
- 端口与随机端口设置；
- 服务控制、Token、断开、复制地址、本机打开、防火墙命令。

本轮目标：

- 服务状态、推荐访问地址和二维码作为第一视觉层级；
- 当前端口、客户端数量作为清晰但次一级的信息；
- 地址列表、端口修改和防火墙说明保持完整，但视觉上不要和主状态抢层级；
- 不删除现有信息，不改变按钮含义、顺序语义或 Remote 行为；
- 推荐地址不要因为窗口放大仍显得像一条弱辅助文字；
- QR 必须保持正方形，不因窗口缩放变形；
- 防火墙文字保留可读性，不要继续使用明显过小的字号。

不新增“复制二维码”“自动诊断”等功能。

---

## 3. 演示文稿页：提高列表与状态辨认度

当前源码中列表还有 10～11px 的路径、时长、模式、规则状态文字。

本轮要求：

- 正文和关键状态优先达到约 12～13px；
- 不要只把字号放大而保持原行高，必须同步调整必要的行高/间距；
- 文件名仍是首要信息；
- 路径为次要信息，但在正常窗口尺寸下应可辨认；
- 时长、模式、规则启用状态在列表中保持稳定对齐；
- 选中项继续使用已有选中态；
- 当前正在放映的文稿状态继续通过已有 `status-text` / `document-text` / `slide-text` 展示，不新增第二套状态模型；
- 通过排版让“当前正在放映”和“当前选中的规则/文稿”更不容易混淆，但不要改变选择逻辑。

如果扩大列表高度可以改善辨认度，可以在现有窗口内部重新分配空间；不要建立复杂响应式布局系统。

---

## 4. 操作按钮层级

保留现有命令和危险确认流程。

要求：

- 常用放映操作（打开、从头、当前页、上一页、下一页、跳转）保持容易找到；
- 黑屏/白屏/恢复、结束/关闭等操作在视觉上与常用操作有适当分组间距；
- “退出演示软件”继续保持危险样式和现有确认弹层；
- 不新增二次确认；
- 不改变任何 `command(...)` / `remote-action(...)` / `rule-action(...)` 的编号、参数或回调语义；
- 不为视觉统一把标准 `LineEdit` / `ComboBox` / `CheckBox` 重写成自绘控件。

---

## 5. 窗口缩放补充边界

上一轮已经把 Remote 改为原生可缩放窗口。

本轮可以让现有区域在窗口放大后利用更多空间，尤其是列表、路径和状态区；但：

- 不增加窗口尺寸保存/恢复；
- 不增加 resize 事件状态机；
- 不为支持更小尺寸重写整页布局；
- 当前 700×620 最小约束可以保留，除非本轮在不增加复杂度的前提下有明确更合理的最小值；
- 不声称源码审核等于系统边框拖拽真机验收。

---

## 6. 禁止扩大范围

本轮不要处理：

- UX-04 的 Tab 顺序、焦点、Enter/Escape 等交互行为；
- UX-05 的 Timer / 大屏 / 时间到窗口；
- 手机 Web；
- Remote HTTP/WebSocket 协议或命令语义；
- Rust 计时、配置、规则同步逻辑；
- PowerPoint / WPS 行为；
- DPI / 窗口创建时序；
- 音频；
- 更新器、版本号、发布脚本；
- 新功能入口、主题切换、搜索、诊断工具。

---

## 7. 持续编码约束：禁止过度防御

- 不增加 SHA / Hash / checksum / 完整性验证；
- 不重复验证同一事实；
- 不增加无必要重试、备用路径、备份恢复链或额外状态机；
- 不制造视觉快照、截图基线或覆盖率测试矩阵；
- 不为纯视觉层级引入新的数据模型；
- 保持最少必要逻辑。

---

## 8. 验证：按风险分层

本轮原则上属于 Slint 视觉与布局修改。

- 完成整轮后最多运行一次 `cargo check`；
- 如果完全没有触碰 Rust 业务逻辑，不跑全量 `cargo test`、Clippy 或 Release build；
- 如果意外必须触碰现有 Rust 映射，只跑直接相关的定向测试，并在 `CODEX_RESULT.md` 解释原因；
- 不新增视觉快照测试。

真实用户验收重点：

1. Remote 边框/角落拖拽放大是否正常；
2. 连接页一眼能找到服务状态、推荐地址和二维码；
3. 端口、客户端数、地址列表和防火墙信息仍完整但层级清楚；
4. 演示文稿列表中文/英文、长文件名和长路径是否比之前更容易辨认；
5. 时长、模式、规则状态是否对齐且不互相挤压；
6. 当前放映状态与当前选择是否容易区分；
7. 常用放映、屏幕控制、关闭/退出操作分组是否清楚；
8. UX-01 配色与 UX-02 设置页布局不要回退。
