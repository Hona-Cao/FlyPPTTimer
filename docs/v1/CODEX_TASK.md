## 持续测试策略：按风险分层

### 小改动 / 定向修 Bug

只跑与改动直接相关的最小测试；没有必要时可以不额外跑 `cargo check`。不要自动追加全量测试、Clippy 或 Release 构建。

### 计时核心 / 配置 / Remote 等中高风险逻辑改动

跑对应模块或对应行为的定向测试，确认本次目标逻辑没有被破坏。不要自动追加全量 gate。

### 一次任务完成、准备交给 ChatGPT / 用户手测

最多运行一次 `cargo test`；如果已有足够的定向验证，可以不重复跑。只记录实际运行过的验证。

### 准备合并、打包或正式发布

仅在明确进入 merge / package / release 收口阶段时统一运行一次：

```powershell
cargo fmt --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test
cargo build --release
```
