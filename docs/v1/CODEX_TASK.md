## 1. 先补 Remote 窗口原生拖拽缩放

当前 `PresentationWindow` 仍使用固定：

```slint
width: 700px;
height: 620px;
```

而 `SettingsWindow` 已经使用 `preferred-width / preferred-height / min-width / min-height`，可以作为直接参照。

整改要求：

- 保持 Remote 默认打开尺寸约为当前 `700 × 620`；
- 改成原生可拖拽调整大小的窗口约束，不增加自绘 resize grip，不增加窗口尺寸状态机；
- 设置合理的最小尺寸，确保现有连接页和演示控制页的重要控件不会因为缩得过小而明显互相覆盖或被裁掉；
- 放大窗口时，现有依赖 `parent.width / parent.height` 的区域应正常扩展；
- 不修改 Remote 业务回调、协议、按钮含义、确认流程或 Web Remote；
- 不为了这个小需求新增配置字段，也不保存/恢复窗口尺寸。

如果当前 Slint 原生窗口只需要把固定 `width/height` 改为 `preferred-* + min-*` 即可完成，就保持这种最小实现。

## 2. UX-02：设置页从“每行卡片”调整为更清晰的分组布局

范围仅限六页现有设置内容、标题、规则区域的排版。**不改变设置项的信息归属、文字、选项、默认值或业务逻辑。**

### 2.1 Section 分组

当前 `FieldRow` 除 section 标题外，大部分设置行自身都有独立白色圆角卡片和边框，长页面视觉分隔过多。

本轮目标：

- 继续使用当前设置模型中的 section 行，不增加第二套设置模型；
- 以现有 section 为分组边界，让同一 section 内的普通字段更像一个连续内容组，而不是每行一张独立卡片；
- section 之间保持明显大于组内的间距；
- 优先使用简单的 Slint Rectangle / Layout 组合，不建立主题框架、额外状态对象或复杂容器层。

### 2.2 标签列与控件列

当前 `FieldRow` 右侧控件基本固定为 `244px`。

要求：

- 在默认窗口和最小窗口下保持标签与控件对齐；
- 给路径、时长、下拉框、按钮合理宽度，不要因为追求统一而强制所有内容完全相同宽度；
- 中文和英文长标签都应有足够空间，可通过合理行高 / 换行解决，不截掉现有文字；
- 不把长路径改成新的弹窗、Tooltip 或额外交互；现有只读路径行为保持。

### 2.3 设置页底部操作条

- `确定 / 取消 / 应用` 始终保持可达；
- 继续固定在窗口底部，不随设置内容滚走；
- `dirty` 提示语义与按钮启用逻辑不变。

### 2.4 文件规则区域

保持现有结构：规则列表 → 操作栏 → 选中规则详情。

只优化：

- 列宽；
- 行内间距；
- 文件名 / 路径 / 时长 / 模式的辨认度；
- 默认尺寸与最小尺寸下的可用空间。

不要改变：

- 规则选择逻辑；
- 多选/批量逻辑；
- 添加、删除、清空、批量操作语义；
- 规则保存模型或配置结构。

本轮主要是 Slint 窗口属性与布局修改。

- 完成整轮后最多运行一次 `cargo check`，确认 Slint 语法和生成绑定可编译；
- 如果没有修改 Rust 设置模型映射，不要额外跑设置模块测试；
- 如果确实因布局需要触碰了设置模型映射，只跑直接相关的定向测试；
- 不跑全量 `cargo test`、Clippy 或 Release build；
- 不新增视觉快照测试。

真实验收由用户手测：

1. Remote 窗口能从系统窗口边缘/角落正常拖拽改变大小；

3. 设置六页在默认尺寸和最小尺寸下都可滚动访问全部内容；
4. 中文/英文长标签、路径和规则编辑区域不互相覆盖；
5. `确定 / 取消 / 应用` 始终可达；
6. UX-01 已确认的配色不要回退。
