## 1. 取消打开“设置 / 远程控制”时的一闪而过窗口

用户点击计时器右键菜单中的“设置”或“远程控制”时，会先看到一个没有完整绘制的窗口一闪而过，随后才出现真正窗口，看起来像闪退。

必须直接使用桌面控制复现，并观察这一瞬间到底创建/显示了哪个 HWND。确认它的窗口标题、类名、尺寸及对应的 Slint 组件/原生窗口来源。

最终行为：

- 点击“设置”后只出现完整的设置窗口。
- 点击“远程控制”后只出现完整的远程控制窗口。
- 不应先显示空白、半绘制、默认尺寸或随后立即消失的中间窗口。
- 设置窗口与远程控制窗口可以正常出现在任务栏。

只修实际找到的显示顺序/窗口创建问题，不用增加专门的验证入口。

## 3. 计时器窗口不得占用任务栏

用户当前每出现一个普通计时器窗口，Windows 任务栏就出现一个任务按钮。这不符合产品要求。

最终规则：

- 普通 Timer 主窗口：不进任务栏。
- “所有屏幕同时显示”产生的每个 Timer overlay：都不进任务栏。
- 大屏计时窗口/时间到覆盖窗口：不进任务栏。
- 设置窗口：正常进入任务栏。
- 远程控制窗口：正常进入任务栏。

直接在真实桌面和任务栏上确认。检查当前窗口是在 `show()` 前还是之后才修改任务栏相关属性，并选择与 Slint/winit 兼容的简单实现。不要破坏已经修好的无框、右键、透明度、圆角和置顶行为。

## 4. 修复计时器跨屏时空白和尺寸异常

用户把计时器窗口从一个显示器拖到另一个显示器时，会出现空白或窗口尺寸异常。

使用真实多显示器直接复现。重点观察跨屏前后：

- 两块屏幕各自 DPI / scale factor
- Slint window scale factor
- WindowRect / ClientRect
- 实际物理尺寸
- `WM_DPICHANGED` 后窗口尺寸与绘制是否同步
- 圆角 Region 是否仍与新的 ClientRect 一致

找到第一次出现尺寸/绘制不一致的位置再修。

目标：

- 从 100% DPI 屏拖到 125%/150% 等不同 DPI 屏时，计时器保持配置中的逻辑宽高和正常比例。
- 时间和背景立即正常绘制，不出现空白区域。
- 圆角不裁掉内容。
- 从高 DPI 屏拖回低 DPI 屏同样正常。
- 现有单屏、所有屏幕同时显示和大屏模式不受影响。

不要通过禁止跨屏、固定物理像素或重建 Timer 来绕过问题。
