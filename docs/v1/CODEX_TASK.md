## 1. 本轮原则

本轮只优化**已经存在的桌面交互**，不增加新功能、不改变业务语义。

主要范围仍是：

- `ui/app-window.slint`；
- 如确实需要极小 Rust 绑定调整才能保持现有语义，可以修改，但必须说明原因并只跑对应定向测试。

不要修改手机 Web。

本轮不要凭空设计新的快捷键体系。只处理源码中现有控件和已有操作路径的可达性、焦点可见性、禁用/只读反馈和明显交互冲突。

---

## 2. PC Remote 自绘按钮的键盘可达性

当前 `RemoteButton` 是 Rectangle + TouchArea，自绘按钮的鼠标行为已有，但需要检查键盘可达性。

要求：

- 优先使用 Slint 已有、轻量的焦点/键盘机制；
- 如果当前自绘按钮无法通过 Tab 获得焦点，则补足最小键盘可达能力；
- 获得键盘焦点时必须有清晰但不过度的可见焦点样式；
- Enter / Space 如能按 Slint 标准按钮习惯直接复用现有 `clicked()`，可实现；不要新增第二套命令回调；
- 禁用按钮不得通过键盘触发；
- 鼠标 hover / pressed / clicked 行为保持不变；
- 不把所有 RemoteButton 替换成另一套复杂组件库；
- 不建立全局焦点状态机。

如果 Slint 当前版本没有简单、稳定的方式实现某项键盘行为，不要绕过框架做低层事件系统；保留现状并在 `CODEX_RESULT.md` 明确记录。

---

## 3. 设置窗口现有输入控件

检查 UX-02 调整后的六页设置控件，只修明确的交互可用性问题。

要求：

- 标准 `LineEdit` / `ComboBox` / `CheckBox` / `Button` 继续使用原生键盘行为，不自绘替换；
- 只读路径继续允许用户选取/复制，但不能编辑；
- disabled 控件保持不可操作，并在视觉上继续能辨认是禁用而不是内容缺失；
- 不增加只读路径的复制按钮、Tooltip、弹窗或右键菜单；
- 滚动设置页时不要新增“滚轮自动改 ComboBox/数值”之类额外交互；如果标准控件现状没有明确问题，不改；
- 设置页底部 `确定 / 取消 / 应用` 的现有语义和 dirty 逻辑不变。

---

## 4. 现有确认层与焦点

当前 PC Remote 有“退出演示软件”确认层，设置页有批量操作层。

只检查和修复明显问题：

- 弹层打开后，背景点击区域不能意外触发下层控件；
- 焦点样式不要被遮罩吞掉或落在不可见控件上；
- 关闭弹层后不要引入额外状态对象或恢复链；
- 不新增二次确认；
- 不改变退出命令、批量保存或取消语义；
- 不自行新增 Esc/Enter 新语义，除非当前标准控件/已有实现已经明确支持且只需接通现有 callback。

---

## 5. 明确禁止扩大范围

本轮不要处理：

- UX-05 的 Timer / 大屏 / 时间到窗口；
- 手机 Web Remote；
- Remote HTTP/WebSocket 协议或命令语义；
- 计时核心、配置格式、文件规则同步；
- PowerPoint / WPS 控制逻辑；
- DPI / 窗口创建时序；
- 音频；
- 更新器、版本号、发布脚本；
- 新菜单、新快捷键、新搜索、新设置项、新诊断功能；
- 为焦点行为建立复杂状态机或自定义事件框架。

---

## 6. 持续编码约束：禁止过度防御

- 不增加 SHA / Hash / checksum / 完整性验证；
- 不重复验证同一事实；
- 不增加无必要重试、备用路径、备份恢复链或额外状态机；
- 不为键盘/焦点制造测试矩阵、截图基线或视觉快照；
- 不因为一个焦点问题重写整个组件体系；
- 最少必要改动，明确失败，不做多层 fallback。

---

## 7. 验证：继续按风险分层

本轮原则上是 Slint 交互层小改动。

- 如果只改 Slint，整轮完成后最多运行一次 `cargo check`；
- 不自动跑全量 `cargo test`、Clippy 或 Release build；
- 如果确实修改 Rust 绑定，只跑直接相关的定向测试，再按需要跑一次 `cargo check`；
- 不新增焦点/视觉快照测试或覆盖率矩阵。

真实验收由用户手测：

1. PC Remote 用 Tab 在可交互控件之间移动时，焦点是否清楚且顺序基本符合视觉顺序；
2. 自绘 Remote 按钮如果本轮实现了键盘触发，Enter/Space 是否只触发一次正确命令；
3. disabled Remote 按钮是否不能被鼠标/键盘误触发；
4. 设置页只读路径是否仍可选取复制但不能输入；
5. disabled 设置控件是否明确且不可操作；
6. 退出确认层与批量设置层打开时，下层控件是否不会被误操作；
7. UX-01～UX-03 已通过的视觉和布局不要回退。
