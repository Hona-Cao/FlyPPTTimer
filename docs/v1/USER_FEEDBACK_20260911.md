## 已确认的源码依据

- 设置底栏原布局 x=parent.width-290、width=290，右边距确实为零。
- Settings 规则详情原高度 76px，内容仅 34px；PC Remote 对应高度 72px。
- 弹窗隐藏测量文本未设置实际正文的 14px 字号，测量宽度与可见正文也不同；ScrollView 没有显式 viewport-height。
- 音频 MCI 失败后确实启动隐藏 PowerShell，创建 WMPlayer.OCX；TTS 主路径本身已经使用 SAPI，不应把两者混为一谈。
- 原 lan_addresses 扫描 ipconfig 各行中的所有私网 IP，可能把网关、DNS、DHCP 地址放入可访问 URL 列表。新的实现仅从 Windows IP Helper 的 FirstUnicastAddress 取得本机地址，不从网关或 DNS 构造 URL。
- show_time_up_window 已有试图设置虚拟桌面尺寸的代码；因此不能只把同一段 SetWindowPos 再写一遍就声称 F09 解决。需核对 Slint/Winit 首帧与后续尺寸，以及实际黑色内容的覆盖范围。
- settings_dpi_proc 同时让 Winit 处理 WM_DPICHANGED，再依据旧客户区做一次校正；这是重点排查处，不是无需复现即可断言的唯一根因。
- updater.rs 的安装更新交接仍包含 PowerShell，音频去脚本不等于整个程序所有分支都已去脚本。Codex 必须区分自动检查与用户确认安装的实际调用路径。

## 直接修改的验证边界

本轮使用临时 User feedback fixes 工作流，先对固定 blob 应用已审阅变更，在 Windows 上格式化、编译、运行现有测试及新增地址选择测试；成功后才提交产品源码。准备阶段失败不算源码已修复，结果以实际 source commit 与流水线输出为准。临时转换脚本在成功提交时删除，不随程序交付。

本轮未直接修改 DPI、TimeUpWindow 的原生生命周期或 Office 控制逻辑。后续由 Codex 执行最新 CODEX_TASK；不能把这三类问题标成已经修好。

## 交付原则

保留全部既有功能和当前总体界面风格。新增 Cargo feature 只能启用当前已锁定 windows-sys 的 IP Helper 类型，不升级任何依赖版本。

Codex 整合 F01/F07/F09 和旧 B1/B2 后，交付一个含真实源码标识、默认配置和必要运行库的绿色 ZIP。不要让用户逐个测试中间包，也不要混用早期同为 1.13.0 的包。最后用户只复核跨屏/整体观感、手机热点、实际声音与到时全屏遮罩；代码调试、错误注入和可自动执行的回归由实现者完成。
