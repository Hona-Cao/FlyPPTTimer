# FlyPPTTimer V1.0 基线清单

> 状态：**V1 实现基线**  
> 产品基线：**FlyPPTTimer v0.30.2**  
> V1 技术方向：**Rust + Slint，Windows 10+ x64**

## 给 Codex / 后续实现者的最高优先级约束

V1.0 不是功能升级，而是一次底层重构。

**V1.0 的功能、用户可见选项、默认值、行为、中文显示文字、英文显示文字必须以 v0.30.2 为唯一产品基线。**

允许改变：

- 实现语言与代码结构
- 性能与资源占用
- 稳定性
- UI 视觉风格
- 排版、间距、圆角、阴影、动画等视觉细节

禁止擅自改变：

- 功能数量
- 设置项数量
- 设置项名称
- 选项数量、顺序和含义
- 默认值
- 中文显示文字
- 英文显示文字
- 快捷键行为
- 托盘和右键菜单行为
- PowerPoint / WPS 行为
- Remote Web 功能与协议
- v0.30.2 用户已有配置的实际语义

### 判定规则

开发中如果出现疑问，只问：

> **v0.30.2 有这个东西吗？**

- v0.30.2 没有：V1 不做。
- v0.30.2 有：名称、选项和行为按 v0.30.2 实现。
- 只是 UI 不够美观：可以重新设计视觉，但不得改变信息与功能。

### 禁止过度工程化

这是个人开源项目。不要为了“工程规范”堆积与产品价值无关的复杂度。

**不要做：**

- SHA256 Artifact 校验流程
- 测试覆盖率指标
- 为 getter / setter 写测试
- 大量 Mock
- GitHub Runner GUI Automation
- 为 GUI 建复杂自动测试框架
- Playwright CI 仅为了重复验证已经稳定的静态页面
- 为单一实现额外创建无必要的 Interface + Factory + Provider 层
- 大量理论性 retry / fallback
- 为极端、几乎不会发生的环境编写大量防御性代码
- 为了兼容重构过程同时长期保留多套 UI

**保留真正影响产品稳定性的简单措施：**

- Timer 使用可靠的单调时间
- 配置保存不能轻易写坏
- PowerPoint / WPS 的 COM / Win32 资源正确释放
- HTTP 服务退出时释放端口
- 程序正常退出
- 基本日志
- 单实例
- Windows 多 DPI / 多屏正常工作

### 必须复刻的细节

只有：

- `时间到后的操作 = 仅提示`
- 且 `继续显示超时 = 开`

时，倒计时到零后才继续显示超时。

如果到时动作是黑屏或退出放映，则按 v0.30.2 行为处理，不擅自改变。

# 18. 最小测试原则

只测试真正容易在重构中改坏、且一旦出错会影响用户的核心逻辑。

## 自动测试建议

- [ ] Timer 状态转换
- [ ] 倒计时 / 正计时 / 超时
- [ ] v0.30.2 配置读取
- [ ] 文稿规则优先级
- [ ] 提醒阈值
- [ ] 少量关键 Remote command

不规定测试数量，不规定覆盖率。

## 发布前人工检查

按实际用户路径检查：

`启动 → Timer → 设置 → PowerPoint → WPS → 双屏 → 声音 → 快捷键 → 手机 Remote → 安装版/便携版`

通过即可。

不要引入 SHA256 发布校验、复杂 GUI 自动验收或大规模 CI 基础设施。

# 19. V4 的使用方式

`agent/v4-foundation` **不是 V1 的产品基线**。

v4 的价值仅用于参考已经踩过的工程坑，例如：

- Timer 单调时间与状态模型
- PowerPoint / WPS COM 处理经验
- Presentation command 边界
- 文稿 ownership
- Remote command 处理
- 多屏 / DPI 经验
- v0.30.2 parity matrix

不要直接继承：

- v4 的 WPF 页面结构
- v4 新增的显示文字
- v4 新的设置分类
- WPF + WinForms 混合架构
- 双 EXE 设计
- 大量 CI / GUI 自动化基础设施

# 20. Codex 实现检查模板

每完成一个 V1 模块，只需要回答以下问题：

1. v0.30.2 对应功能是否全部存在？
2. 是否擅自增加了 v0.30.2 不存在的功能或设置项？
3. 用户可见中文是否与 v0.30.2 一致？
4. 用户可见英文是否与 v0.30.2 一致？
5. 默认值和行为是否一致？
6. 是否为了“架构/测试完整”加入了不必要的复杂度？
7. UI 是否在不改变功能和文字的前提下得到视觉改善？

只要 1–5 有一项不满足，就不算完成。
