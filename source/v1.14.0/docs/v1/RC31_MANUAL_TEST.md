# FlyPPTTimer 1.13.0 — ChatGPT RC3.1 手动验收

仅测试本轮 `chatgpt-rc31` 测试包。所有 Office 文稿必须使用可丢弃副本；不要拿真实未备份文稿做“关闭不保存”测试。

已由自动检查覆盖的内容（fmt / clippy / Rust tests / release build）不需要人工重复。用户此前已经确认的最终尺寸稳定、滚动条、作者说明、手机基本控制、音频基本播放和全屏黑屏基础效果也不重做。

## 必测 1：ESC 普通短按解除“时间到”遮罩

1. 把“时间到后的操作”设为黑屏并显示“时间到”。
2. 用 2～3 秒短计时触发全屏遮罩。
3. 像正常按键一样短按一下 ESC，不要故意长按。
4. 连续重复 10 次。

通过：每次普通短按都能立即解除遮罩；不要求按住 200～300ms；不会顺带重置/启动计时器。

## 必测 2：已经在放映的目标文稿重新成为控制目标

准备可丢弃 A.pptx、B.pptx。

1. 让 A 已经处于 Slide Show。
2. 在电脑端把 B 的编辑窗口切到前台，使活动文稿不是 A，但不要结束 A 的放映。
3. 手机 Web Remote 演示列表点 A 的“当前/切换/打开”入口。
4. 再按手机“下一页”“上一页”，可再试一次跳转页码。

通过：A 的放映不被重启、不闪退；A 成为当前受控目标；随后翻页/跳转控制 A，不出现“未能按目标文稿匹配放映窗口”，也不误控制 B。

## 必测 3：关闭未保存文稿不再卡死 Office worker

只用可丢弃文稿。

### 3A 用户原先打开的文稿

1. 手工打开 A.pptx，随便修改一处但不要保存。
2. 手机 Web Remote 选择“关闭当前文稿”，在确认框确认。
3. 观察是否出现 Office 的“是否保存”弹窗。
4. 关闭后立刻用手机执行刷新/打开另一份文稿/开始放映之一。

### 3B FlyPPTTimer 打开的文稿

1. 由手机打开 B.pptx。
2. 在电脑端修改 B 但不要保存。
3. 手机确认关闭当前文稿，再立即执行一个演示命令。

通过：两种情况都直接按“关闭且不保存”的既定语义完成，不出现保存确认框，不发生 15 秒/长期无响应；关闭后演示控制仍能继续。磁盘文件保持关闭前最后一次真实保存的内容。

## 必测 4：手机排序后，电脑新增规则必须追加到末尾

1. 准备 A、B、C 三条文件规则，在手机端排成一个明显的自定义顺序，例如 C、A、B。
2. 在 Settings 或 PC Remote 的规则管理页从电脑新增 D。
3. 手机刷新或等待自动刷新。
4. 重启 FlyPPTTimer 后再看一次顺序。

通过：原来的 C、A、B 顺序不变，D 追加在末尾；不会因为 D 的默认顺序值把 D 插到列表顶部或中间。重启后顺序保持。

## 仍需环境条件才能最终确认

这些不是本轮源码回归失败，而是自动/当前家用环境无法替代的现场条件：

- **真实手机恢复/触控**：连续使用约 10 分钟；锁屏 20～30 秒、切后台、断开再恢复 Wi-Fi 后，在 token/port 未变时无需重新扫码；Next/Close 不应重复执行。
- **原生 Microsoft PowerPoint**：若电脑确实有未被 WPS 接管的 PowerPoint COM，用可丢弃 A/B 再做一次不同文稿切换、从头/当前页放映与关闭；WPS 已有较多实测证据。
- **150%/125% 混合 DPI**：仅观察 Settings、PC Remote、Timer 在鼠标仍按住跨屏边界时是否仍有瞬时内容错位；最终尺寸不累计漂移此前已经通过，不需要重做长时间绕屏。

反馈时只需写“项目编号 + 通过/失败 + 现象”。若截图包含 Remote 二维码、token、文件路径，请先遮挡。
