# 2026-09-11 第二轮用户实测与优化要求

版本仍为 1.13.0 review；分支 `codex/v1-06-manual-test`。本文件记录用户对 `bf00cf0` 反馈整改包的真实结果和下一轮产品要求。不得用此前自动测试覆盖这里的用户实测结论。

## 一、用户已经确认通过

- 跨屏拖动后最终窗口尺寸稳定，未再出现累计放大/缩小。
- ScrollView 不再遮挡中间控件。
- “作者的话”弹窗显示正常。
- 手机 Remote 已能正常连接和控制。
- 提示音频播放正常。
- “时间到”全屏黑屏显示正常。

这些通过项不应在下一轮被推倒重做。

## 二、仍需收口的现象

### U01 跨屏拖动中的瞬时错位

窗口跨不同 DPI 屏幕拖动期间仍可能出现内容/显示错位；松开鼠标后会自行恢复。最终尺寸已稳定，因此本轮目标不是重做 F01，而是消除拖动过程中的瞬时视觉不同步。

要求保留现有无累计尺寸漂移的修复。不得用固定窗口尺寸、禁用 DPI、禁止跨屏拖动、递归 SetWindowPos 或松手后再补一层延迟校正掩盖问题。

### U02 滚动条与内容间距

滚动条已不遮挡，但与中间控件仍太近。增加稳定 gutter，让内容区与滚动条有明显呼吸空间；不扩大成主题重做。

### U03 其他文本弹窗

“作者的话”已通过。继续检查其他长文本/错误/确认弹窗，至少覆盖中英文、普通和长文本、125%/150% 可用 DPI，确保不裁字、不盖按钮、可滚动内容能到达末尾、键盘操作正常。

## 三、新的操作与功能优化

### U04 时间到黑屏支持 ESC

电脑端出现应用自己的“时间到”全屏黑屏时，按 ESC 应立即解除该黑屏。F4 / Remote Reset 等既有解除通道继续保留。

只解除 FlyPPTTimer 的时间到遮罩，不拦截系统安全快捷键，不改变 PowerPoint 自己的 ESC 语义。

### U05 提示音最多播放 10 秒，并保留原文件名

- 单次提示音实际可听播放时间最多 10 秒；短于 10 秒的文件自然播完。
- 到 10 秒必须停止本次提示音，不能让长音频继续干扰汇报。
- TTS 不因这个要求被截断，除非之后用户另行要求。
- 选择提示音后仍复制到程序自己的提示音目录，但复制后的文件名必须保留用户所选文件的原始 basename，不得改成 `prompt1.wav` / `end.mp3` 一类槽位名。
- 三个提示槽可以使用同名文件而互不覆盖，可用每槽子目录解决；不要通过给文件名加随机后缀来规避。

### U06 手机端演示操作先自动退出“时间到”遮罩

Web/mobile Remote 的“演示”页中，除纯状态刷新外，任何用户主动演示操作在执行前如果存在 FlyPPTTimer 的“时间到”黑屏，都先解除该遮罩，再执行原命令。

例如：上一页、下一页、跳转、从头放映、从当前页放映、打开/切换文件、黑/白屏、结束放映、关闭文稿、退出演示软件，都不再要求用户先单独点“退出时间到黑屏”。

原独立“退出时间到黑屏”按钮可以保留，作为显式恢复通道。

### U07 切换文件时先结束其他正在播放的幻灯片放映

用户复现：手机端直接切换/打开另一个文件时，新文件被置顶，但旧文件仍在 Slide Show，导致计时生命周期仍被旧放映占用。

目标：当用户选择/打开/启动一个**不同目标文稿**，且当前另一个文稿正在放映时，在同一个串行的 Presentation STA 操作中：

1. 先结束当前旧放映；
2. 再打开/激活目标文稿；
3. 如果原命令是“从头放映/从当前页放映”，继续启动目标文稿的对应放映；
4. 不因为“切换”而关闭旧文稿，更不能保存或改写用户旧文稿；
5. 计时生命周期最终绑定新放映/新规则，不能继续被旧放映占用。

不要在 Web 客户端连续发送 `EndShow` + `Open` 两个独立命令；当前 PresentationService 有 busy/串行状态，这样会产生竞态。应在同一个 Presentation worker 高层命令中完成切换。

同类流程优化：关闭一个当前正在放映的文稿时，先结束该文稿放映再执行既有的关闭确认语义；Force Quit 仍保留危险确认；Previous/Next 在没有放映时不要擅自自动启动放映。

### U08 手机演示文件列表管理

手机端演示文件列表需要：

- 隐藏：隐藏已汇报文件，减少列表干扰；隐藏只影响手机列表可见性，不等于 `rule.enabled=false`，不能破坏文件计时规则。
- 恢复隐藏：必须能查看隐藏项并恢复，不能一旦隐藏就找不回来。
- 删除：删除的是 FlyPPTTimer 保存的列表/文件规则条目，必须二次确认；绝不删除磁盘上的 PPT/PPTX/PDF 文件，也不因删除列表项自动关闭已打开文稿。
- 添加：允许把文件加入受控列表。优先安全方案：将当前已打开但尚未成为规则的文稿加入列表；如提供“在电脑选择文件”，应调用电脑端现有原生文件选择器，不在手机上暴露任意电脑文件系统，不默认增加文件上传协议。
- 排序：支持触屏友好的手工顺序并持久保存。可用上移/下移或稳定的拖拽柄；不要每次轮询按活动状态自动重排而打乱用户顺序。

当前活动文稿仍应清楚标识。对“仅已打开、尚未保存为规则”的条目不要提供会误解为删除磁盘文件的危险操作。

### U09 Remote 稳定与断线重连

用户现在能连接，但使用中经常看到断联。目标：短时 Wi-Fi 抖动、手机锁屏/切后台后回前台、浏览器暂停计时器等场景应自动恢复，不要求重新扫码。

要求：

- 状态轮询单次偶发失败不能立刻把 UI 判定为永久断线；连续失败后再显示断开。
- `online`、页面恢复前台、窗口重新获得焦点时立即尝试同步。
- 自动重连只重试状态读取；不可盲目自动重发可能非幂等的 POST 演示命令，以免一条 Next/Close 被执行两次。
- token / port 未变时，断线恢复不要求新二维码；若 token/port 真正变更，则现有刷新逻辑继续生效。
- 不为了“稳定”关闭鉴权、防火墙或改成公网服务。

### U10 Timer 显示当前页/总页数

普通计时器窗口在时间下方可显示 `当前页/总页数`，例如 `1/23`。

- 新设置：“显示当前页/总页数”，默认开启。
- 只在能取得有效演示页码时显示；没有可用页数时不显示 `0/0`。
- 页码为次要信息，字号小于主计时文字，居中，视觉层级清楚。
- 普通 Timer 和多屏镜像 Timer 保持一致；大屏 Timer 也应评估一致性并避免布局突兀。
- 页码变化不能重置计时器、不能写磁盘、不能造成窗口尺寸频繁抖动。

### U11 Timer 内容自适应尺寸 + 设置实时预览

现有 `expand_timer_windows_if_needed` 只会扩大并把扩大结果写回 `Appearance.Width/Height`，不能作为最终实现继续叠加。

目标：

- `Appearance.Width/Height` 保留为用户手工基准/最小尺寸；实际 Timer 可根据当前内容需要自动增大或缩回该基准。
- 时间单独显示与时间+页码双行显示都能得到合适尺寸，不截字、不留异常大空白。
- 自动内容适配的临时实际尺寸不要每秒写回配置；否则一旦变大就失去缩回能力，也会产生无意义磁盘写入。
- 不再建立第二套与 `sync_timer_window_scale` 争夺尺寸的循环；混合 DPI 下必须只有明确的尺寸来源，避免恢复此前跨屏漂移。
- Settings 中手工修改 Timer 宽、高、字号时，计时器窗口立即预览，不必点“应用”。
- 实时预览只影响运行态/预览态，不提前提交整个 Settings draft，不提前写磁盘。Cancel/放弃修改后恢复最后一次已应用值；Apply 后才持久化。
- 页码显示开关也应能够实时预览。

除非确有必要，不额外增加“自动尺寸”开关；优先把 Width/Height 定义为稳定的手工最小尺寸，这样既保留手工控制又自动防止文字裁切。

## 四、本轮避免的范围扩张

- 不换技术栈、不升级 Slint/Rust/依赖、不创建新的大框架。
- 不恢复 PC Remote 已删除的演示控制按钮；上述演示流程优化针对 Web/mobile Remote 与底层 PresentationService。
- 不重做已经通过的手机 LAN 地址/token、音频原生 COM、全屏遮罩几何、Office 数据安全等修复。
- 不创建 Release/Tag，不合并默认分支，版本先保持 1.13.0 review。
